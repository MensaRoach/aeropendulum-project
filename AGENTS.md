# Aeropendulum Project Architecture & Guidelines

This document provides context and guidelines for autonomous agents (LLMs) assisting with the Aeropendulum project.

## Overview
This is a hobby embedded systems project for an Aeropendulum, designed to be built across multiple platforms (Windows/macOS) using VS Code as the development environment and STM32CubeCLT as the toolchain.

## Directory Structure
- `BOARDS/` - Contains the board-specific code generated by STM32CubeIDE. Each board has its own subdirectory (e.g., `NUCLEO-F401RE`). The code here is generated using Low-Level (LL) drivers (`USE_FULL_LL_DRIVER`), not HAL. **Do not manually modify the CubeIDE-generated files in this directory unless absolutely necessary.**
- `APPS/` - Contains the custom application code. `APPS` compiles into a static library (`libapps.a`) and is linked to the board's executable. All your custom logic, controllers, and application flow should live here.
- `.cmake/` - Contains our custom CMake logic to bridge the STM32CubeIDE project structure with our CMake-based build system. It includes the toolchain file and scripts to discover and compile the CubeIDE sources.
- `.build/` - The CMake build output directory (ignored by git).

## Build System
We use a custom CMake architecture to wrap the STM32CubeIDE projects.
1. `CMakePresets.json` defines the shared presets (`default`, `Debug`, `Release`) and sets up Ninja as the generator.
2. `CMakeUserPresets.json` (ignored by git) defines the developer's local environment. It must contain the `PATH` override pointing to the local STM32CubeCLT installation.

### Building
To build, run:
```bash
cmake --preset Debug-Local
cmake --build .build/Debug-Local
```

## Rules for Agents
1. **Never use CubeMX CMake generators:** The project uses STM32CubeIDE project formats. If you need to add new files to the build, ensure they are globbed correctly in `.cmake/stm32.cmake` or linked in `APPS/CMakeLists.txt`.
2. **Use LL Drivers:** The peripheral initialization uses STM32 Low-Level (LL) drivers. Use LL driver functions instead of HAL driver functions when interacting with hardware.
3. **Paths:** Ensure you respect `.build/` and `.cmake/` as hidden directories.
4. **Target Linking:** When creating new components, link them against the `${BOARD_NAME}_config` interface library to inherit the correct hardware definitions and include paths.
